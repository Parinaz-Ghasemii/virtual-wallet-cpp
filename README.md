# Jib Pool – a virtual wallet, built in stages

A small virtual-wallet ("digital wallet") system that grew over two assignment phases of a university programming course. It starts with a hand-written hash function and RSA, and ends with an object-oriented C++ console application that signs users up, enforces permissions and keeps its data in files.

It is a learning project: the point was the design and the implementation of the pieces (hashing, RSA, fee rules, file persistence, OOP), not production security.

## What the wallet does

- Holds balances in several virtual currencies, each with a value relative to the base currency `jibCoin`.
- Supports **deposit**, **withdraw**, **exchange** (convert one currency to another) and **transfer** (between users).
- Charges fees: a percentage for small amounts, a flat 10 `jibCoin` equivalent for large ones. Fees go to a special **exchange account** (`SARAFI`), which also acts as the counterparty for deposits, withdrawals and exchanges.
- Reports `Insufficient Funds`, `Invalid User` and `Invalid Command` errors.

## Build and run

Requires `gcc`/`g++` and `make`.

```bash
make            # builds everything into build/
make test       # runs all programs against samples/
```

Programs read from standard input, for example:

```bash
./build/03_multi_user_transfers < samples/03_multi_user/s2.in
```

The console app expects its data files (`currencies.txt`, one `<Currency>.txt` per currency, `users.txt`) in the current directory; the first line of each currency file and of `users.txt` is the exchange account. `tests/run_tests.sh` shows a complete working setup.

## Design notes

**Hash function.** Every character is mapped to `((3·ascii + 17) mod 26) + 65`. The values of all characters whose index has the same remainder mod 16 are summed to produce each of the 16 output characters. It is deliberately simple and not collision-resistant.

**RSA.** Two primes `p`, `q` give `n = p·q` and `φ = (p-1)(q-1)`. `e` is the smallest value coprime to `φ`, and `d` is found from `d = (k·φ + 1) / e`. Text is encrypted character by character. In phases 1–2 the system uses `p = 101`, `q = 19` (`n = 1919`) for incoming commands; the console app generates a fresh key pair per user from consecutive primes and shows the private key once at sign-up (only the public part is stored).

**OOP structure (phase 2).**
- `Wallet` owns the list of currencies and accounts and is the only class allowed to touch an account's private balances (via `friend`). All commands are methods on `Wallet`.
- `Account` stores balances privately; `Sarafi` (the exchange account) inherits from it.
- In the console app, the logged-in role decides which commands are allowed: customers may `TRANSFER`, `WITHDRAW`, `EXCHANGE`, `REPORT` on their own account; only the exchange account may `DEPOSIT`.

**Persistence (console app).** One text file per currency (`<user> <balance>`), `users.txt` (id, hashed password, public key), `currencies.txt`, and an append-only `log.txt` (`<user> <command> <1|0>`). Files are updated immediately after each change, and the state is reloaded on start-up.

## Tests

`make test` runs 14 checks: the three problem statements' samples where they were given, plus scripted multi-session runs of the file-based programs.

Note: the problem statements' sample output was cut off on the right for a few long lines. For those cases (`01_hash_rsa` s2/s3, `03_multi_user` s1) the visible part of the expected output was verified by hand and the rest was filled in from the program's output, so they work as regression tests rather than independent ground truth. The encrypted inputs for `03_multi_user` were regenerated by encrypting the decoded commands and checked against the numbers visible in the statement.

## Known limitations / what I would improve

- Console app: one command per session (it should loop until `Exit`), and error messages such as `Insufficient Funds` are logged as failures but not printed to the user.
- Crypto helpers in the console app are free functions; they belong inside the classes.
- Money is stored as `float`; integer cents or a decimal type would be correct.
- Fixed-size arrays (100 accounts/currencies) and variable-length arrays (a compiler extension in C++); `std::vector` would remove both limits.
- The hash and RSA here are toy implementations with tiny primes. Never use them for real security.
- Command names follow the assignment text, including its `WITHDRAWL` spelling in phase 1 problems 1–2.
